# Tracefold

Открытый инструмент для изучения потоков средств между блокчейн-адресами.

> **Статус проекта: ранний прототип.** Основной граф, подписи кошельков и балансы пока содержат демонстрационные данные. Таблица последних транзакций показывает сохранённые наблюдения добавленных кошельков и будет пустой, пока история не синхронизирована через настроенный источник. Панель риска загружает сигналы аналитика для выбранного адреса и может учитывать точное совпадение OFAC SDN после явной проверки локального снимка; версия оценки предварительная и не является юридическим выводом или полной комплаенс-проверкой. В панели кошелька доступна ручная синхронизация. Необязательный Compose `sync-worker` периодически обновляет отслеживаемые Bitcoin и поддерживаемые EVM-адреса с целевым интервалом пять минут при достаточной мощности провайдера; это ограниченный опрос истории, а не мониторинг в реальном времени или всего mempool. EVM-граф использует точные сохранённые поля отправителя и получателя и не выводит контрагентов Bitcoin. Поддерживаются Ethereum, Base и Arbitrum One.

**Документация:** [Русский](README.ru.md) · [Українська](README.uk.md) · [English](README.md)

## О проекте

Tracefold задуман как OSINT-инструмент для расследований. Аналитик сможет начать с адреса, проследить переводы в поддерживаемых сетях, сохранить основания каждой связи и проверить сигналы риска. Алгоритмическая оценка не должна восприниматься как доказательство.

Прототип интерфейса включает демонстрационный обзорный граф и отдельный граф EVM-связей по сохранённой истории, фильтры сетей, таблицу сохранённых наблюдений и объяснимую версионируемую оценку выбранного сохранённого кошелька.

## Принципы

- Для каждой находки показывать сеть, адрес, ссылку на транзакцию, источник и время наблюдения.
- Разделять наблюдаемые транзакции, пользовательские подписи и гипотезы аналитика.
- Показывать сеть как предположение, которое нужно подтвердить: адрес формата EVM может существовать в Ethereum, Base, Arbitrum и других совместимых сетях.
- Называть оценку индексом подверженности, а не вероятностью или доказательством нарушения.
- Показывать полноту покрытия и актуальность данных; не создавать впечатление, что отслеживаются все кошельки и сети.

## Текущий стек

- **Frontend:** React, TypeScript, Vite и Tailwind CSS.
- **API:** локальный сервис на Rust и Axum.
- **Постоянные данные:** PostgreSQL; начальная миграция создаёт таблицы расследований, отслеживаемых адресов и сигналов риска.
- **Очередь и координация:** Redis Streams для фонового worker-а; API также проверяет доступность Redis в readiness endpoint.

API поддерживает создание и просмотр расследований и отслеживаемых адресов, ручную синхронизацию истории Bitcoin и выбранных EVM-сетей, сигналы риска от аналитика и проверку точного адреса по импортированному снимку OFAC SDN. Таблица последних транзакций показывает сохранённые наблюдения. Панель риска загружает сигналы выбранного кошелька и показывает предварительную оценку версии модели с вкладом каждого сигнала; точное совпадение OFAC добавляется как прямое санкционное доказательство только после явной проверки, отсутствие совпадения балл не снижает. Compose worker обновляет отслеживаемые адреса через те же ограниченные адаптеры провайдеров; см. [описание фоновой синхронизации](docs/ru/continuous-sync.md). Отдельный граф связей строится по сохранённым полям отправителя и получателя EVM; входы и выходы Bitcoin не раскрывают контрагентов и не включаются в этот граф. Основной граф и балансы используют демоданные. API не имеет аутентификации и предназначен только для локальной разработки. Снимок OFAC обновляется вручную; коммерческий сервис проверки не подключён.

- `GET` / `POST` `/api/v1/investigations`
- `GET` / `POST` `/api/v1/investigations/{investigation_id}/addresses`
- `POST` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/sync`
- `GET` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/transfers`
- `GET` / `POST` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals`
- `GET` / `PUT` / `DELETE` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals/{signal_id}`
- `GET` `/api/v1/screening/address?network=ethereum&address=0x...`

Инструкция по загрузке снимка и покрытию: [проверка OFAC](docs/ru/ofac-screening.md).

## Синхронизация истории транзакций

Ручная синхронизация доступна через интерфейс; Compose worker также периодически обновляет все отслеживаемые адреса с целевым интервалом пять минут, если хватает ресурсов провайдера и worker-а. Для Bitcoin используется Blockstream Esplora. Для EVM — REST v2 Blockscout: Ethereum (chain ID 1), Base (8453) и Arbitrum One (42161); другие EVM-сети не поддерживаются. Настройки: `BLOCKSCOUT_BASE_URL` (по умолчанию `https://api.blockscout.com`) и необязательный `BLOCKSCOUT_API_KEY` (передаётся как bearer-токен; доступ поставщика может требовать ключ). Секреты в репозитории не хранятся. См. [инструкцию по фоновой синхронизации](docs/ru/continuous-sync.md).

Синхронизация Bitcoin сохраняет прежнее ограниченное поведение Esplora. Для EVM параллельно загружаются обычные нативные транзакции, успешные внутренние переводы нативной валюты и события ERC-20. Сохраняются целые исходные суммы, адрес контракта и необязательное число decimals, индекс события, адреса сторон, блок, время и хост источника. Каждый поток EVM ограничен 10 страницами по 50 записей; `may_have_more_history` показывает, что на лимите у поставщика была следующая страница. Это ограниченная история, а не полный индекс: другие сети, стандарты токенов и пропуски поставщика не покрываются. Несколько событий одной транзакции хранятся отдельно. Endpoint переводов возвращает до 500 последних записей. Worker опрашивает историю, но не отслеживает каждый блок или mempool-событие.

## Запуск локального API

Требуется Docker Compose.

```sh
docker compose --env-file .env.example up --build -d
```

Пример конфигурации использует учётные данные только для локальной разработки. Compose публикует сервисы на loopback; не открывайте этот API без аутентификации в сеть. Проверить состояние можно по адресам:

- `http://127.0.0.1:8080/health/live`
- `http://127.0.0.1:8080/health/ready` — проверяет PostgreSQL и Redis.

Остановить сервисы, сохранив данные базы, можно командой:

```sh
docker compose --env-file .env.example down
```

## Запуск прототипа интерфейса

Требования: Node.js 20.19+ или 22.12+ и npm.

```sh
npm ci
npm run dev
```

Vite выведет локальный адрес приложения. Сейчас оно использует встроенные демонстрационные данные; API-ключ не нужен.

## Источники данных и лицензирование

Синхронизация Bitcoin и выбранных EVM-сетей получает историю через Blockstream Esplora и Blockscout вручную и через фоновый Compose worker. Эти данные описывают транзакции, но не атрибутируют личности и не обеспечивают полный анализ риска кошельков. Можно локально импортировать официальный снимок OFAC SDN и выполнять точную проверку адресов Bitcoin и Ethereum; обновление выполняется вручную. API не использует веб-поиск OFAC для автоматических запросов ([FAQ OFAC](https://ofac.treasury.gov/faqs/287)). Коммерческие аналитические сервисы требуют отдельной лицензии.

Не отправляйте приватные ключи, seed-фразы и секреты. Tracefold задуман как watch-only инструмент. Сигналы риска помогают начать проверку, но не являются юридической консультацией, доказательством личности или автоматическим основанием для блокировки средств или отказа в обслуживании.
