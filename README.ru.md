# Tracefold

Открытый инструмент для изучения потоков средств между блокчейн-адресами.

> **Статус проекта: ранний прототип.** Граф, подписи кошельков, балансы, таблица транзакций и сигналы риска в интерфейсе — демонстрационные данные. API может по запросу получать историю Bitcoin через Blockstream Esplora и историю EVM через Blockscout; постоянного мониторинга нет. EVM-поддержка ограничена Ethereum, Base и Arbitrum One. Санкционные данные и коммерческие сервисы проверки не подключены. Не используйте демонстрационные значения для операционных или комплаенс-решений.

**Документация:** [Русский](README.ru.md) · [Українська](README.uk.md) · [English](README.md)

## О проекте

Tracefold задуман как OSINT-инструмент для расследований. Аналитик сможет начать с адреса, проследить переводы в поддерживаемых сетях, сохранить основания каждой связи и проверить сигналы риска. Алгоритмическая оценка не должна восприниматься как доказательство.

Прототип интерфейса включает граф потоков, фильтры сетей, таблицу последних переводов и объяснимый демонстрационный индекс риска.

## Принципы

- Для каждой находки показывать сеть, адрес, ссылку на транзакцию, источник и время наблюдения.
- Разделять наблюдаемые транзакции, пользовательские подписи и гипотезы аналитика.
- Показывать сеть как предположение, которое нужно подтвердить: адрес формата EVM может существовать в Ethereum, Base, Arbitrum и других совместимых сетях.
- Называть оценку индексом подверженности, а не вероятностью или доказательством нарушения.
- Показывать полноту покрытия и актуальность данных; не создавать впечатление, что отслеживаются все кошельки и сети.

## Текущий стек

- **Frontend:** React, TypeScript, Vite и Tailwind CSS.
- **API:** локальный сервис на Rust и Axum.
- **Постоянные данные:** PostgreSQL; начальная миграция создаёт таблицы расследований, отслеживаемых адресов и сигналов риска.
- **Кэш и координация:** Redis; API проверяет его доступность в readiness endpoint.

API поддерживает расследования, отслеживаемые адреса и ручную синхронизацию Bitcoin и выбранных EVM-сетей. Граф, балансы, панель риска и основная таблица транзакций пока используют демоданные. В API нет аутентификации; он предназначен только для локальной разработки. Постоянной синхронизации, санкционного источника и коммерческого сервиса проверки нет. Таблица `risk_signals` создана, но API для работы с сигналами риска ещё не реализован.

- `GET` / `POST` `/api/v1/investigations`
- `GET` / `POST` `/api/v1/investigations/{investigation_id}/addresses`
- `POST` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/sync`
- `GET` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/transfers`

## Синхронизация истории транзакций

Синхронизация истории запускается только по запросу. Для Bitcoin используется Blockstream Esplora. Для EVM — REST v2 Blockscout: Ethereum (chain ID 1), Base (8453) и Arbitrum One (42161); другие EVM-сети не поддерживаются. Настройки: `BLOCKSCOUT_BASE_URL` (по умолчанию `https://api.blockscout.com`) и необязательный `BLOCKSCOUT_API_KEY` (передаётся как bearer-токен; доступ поставщика может требовать ключ). Секреты в репозитории не хранятся.

Синхронизация Bitcoin сохраняет прежнее ограниченное поведение Esplora. Для EVM параллельно загружаются обычные нативные транзакции, успешные внутренние переводы нативной валюты и события ERC-20. Сохраняются целые исходные суммы, адрес контракта и необязательное число decimals, индекс события, адреса сторон, блок, время и хост источника. Каждый поток EVM ограничен 10 страницами по 50 записей; `may_have_more_history` показывает, что на лимите у поставщика была следующая страница. Это история по запросу, а не полный индекс: другие сети, стандарты токенов и пропуски поставщика не покрываются. Несколько событий одной транзакции хранятся отдельно. Endpoint переводов возвращает до 500 последних записей; фонового опроса нет.

## Запуск локального API

Требуется Docker Compose.

```sh
docker compose --env-file .env.example up --build -d
```

Пример конфигурации использует учётные данные только для локальной разработки. Compose публикует сервисы на loopback; не открывайте этот API без аутентификации в сеть. Проверить состояние можно по адресам:

- `http://127.0.0.1:8080/health/live`
- `http://127.0.0.1:8080/health/ready` — проверяет PostgreSQL и Redis.

Остановить сервисы, сохранив данные базы, можно командой:

```sh
docker compose --env-file .env.example down
```

## Запуск прототипа интерфейса

Требования: Node.js 20.19+ или 22.12+ и npm.

```sh
npm ci
npm run dev
```

Vite выведет локальный адрес приложения. Сейчас оно использует встроенные демонстрационные данные; API-ключ не нужен.

## Источники данных и лицензирование

Синхронизация Bitcoin по запросу получает историю транзакций из публичного API Blockstream Esplora. Эти данные описывают транзакции, но не атрибутируют личности и не обеспечивают полный анализ риска кошельков. Санкционные наборы и коммерческие сервисы проверки не подключены. Для будущих адаптеров нужно документировать условия поставщика, покрытие, периодичность обновления, правила атрибуции и ограничения на распространение данных. Для санкционного скрининга следует использовать официальные машиночитаемые наборы, если это разрешают их условия. OFAC указывает, что веб-инструмент поиска предназначен для индивидуальных запросов, а не постоянных автоматических проверок ([FAQ OFAC](https://ofac.treasury.gov/faqs/287)). Коммерческие аналитические сервисы требуют отдельной лицензии.

## Безопасность и ответственное использование

Не отправляйте приватные ключи, seed-фразы и секреты. Tracefold задуман как watch-only инструмент. Сигналы риска помогают начать проверку, но не являются юридической консультацией, доказательством личности или автоматическим основанием для блокировки средств или отказа в обслуживании. Соблюдайте применимое законодательство и условия поставщиков данных.
