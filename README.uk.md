# Tracefold

Відкритий інструмент для дослідження руху коштів між блокчейн-адресами.

> **Стан проєкту: ранній прототип.** Граф, мітки гаманців, транзакції, баланси та сигнали ризику зараз є демонстраційними даними. Блокчейн-індексатор, санкційні джерела й комерційні сервіси перевірки не підключені. Не використовуйте показані значення для операційних чи комплаєнс-рішень.

**Документація:** [Русский](README.ru.md) · [Українська](README.uk.md) · [English](README.md)

## Про проєкт

Tracefold задуманий як OSINT-інструмент для розслідувань. Аналітик зможе почати з адреси, простежити перекази в підтримуваних мережах, зберегти підстави кожного зв’язку та перевірити сигнали ризику. Алгоритмічну оцінку не слід сприймати як доказ.

Прототип інтерфейсу містить граф потоків, фільтри мереж, таблицю останніх переказів та пояснюваний демонстраційний індекс ризику.

## Принципи

- Для кожної знахідки показувати мережу, адресу, посилання на транзакцію, джерело і час спостереження.
- Відокремлювати спостережувані транзакції від користувацьких міток і гіпотез аналітика.
- Показувати мережу як припущення, яке треба підтвердити: адресу формату EVM можна використовувати в Ethereum, Base, Arbitrum та інших сумісних мережах.
- Називати оцінку індексом ризикової експозиції, а не ймовірністю чи доказом порушення.
- Показувати повноту покриття й актуальність даних; не створювати враження, що відстежуються всі гаманці та мережі.

## Запланований стек

- **Frontend:** React, TypeScript, Vite, Tailwind CSS.
- **API та обробка:** Rust з Axum.
- **Постійні дані:** PostgreSQL.
- **Кеш і короткочасна координація:** Redis.

Backend, схема бази даних, адаптери джерел і production-модель ризику ще не готові.

## Запуск прототипу інтерфейсу

Вимоги: Node.js 20.19+ або 22.12+ та npm.

```sh
npm ci
npm run dev
```

Vite виведе локальну адресу застосунку. Зараз він використовує вбудовані демонстраційні дані; ключ API не потрібен.

## Перевірки

```sh
npm run lint
npm run format:check
npm run build
```

Інструкції для Rust буде додано разом з API.

## Джерела даних і ліцензування

У прототипі немає сторонніх атрибуцій чи санкційних даних. Для майбутніх адаптерів потрібно документувати умови постачальника, покриття, частоту оновлення, правила атрибуції та обмеження на поширення даних. Для санкційного скринінгу варто використовувати офіційні машинозчитувані набори, якщо це дозволяють їхні умови. OFAC зазначає, що вебінструмент пошуку призначений для індивідуальних запитів, а не для постійних автоматичних перевірок ([FAQ OFAC](https://ofac.treasury.gov/faqs/287)). Комерційні аналітичні сервіси потребують окремої ліцензії.

## Як долучитися

Будемо раді issues і pull request. Пропонуючи нове джерело даних або зміну скорингу, опишіть походження даних, ліцензію чи умови використання, оновлення та спосіб перевірки сигналів аналітиком. Відокремлюйте факти спостереження від висновків.

Ліцензію репозиторію ще не обрано. Перед безпечним повторним використанням або поширенням коду потрібно додати файл ліцензії.

## Безпека та відповідальне використання

Не надсилайте приватні ключі, seed-фрази чи секрети. Tracefold задуманий як watch-only інструмент. Сигнали ризику допомагають почати перевірку, але не є юридичною консультацією, доказом особи чи автоматичною підставою для блокування коштів або відмови в обслуговуванні. Дотримуйтеся чинного законодавства й умов постачальників даних.
