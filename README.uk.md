# Tracefold

Відкритий інструмент для дослідження руху коштів між блокчейн-адресами.

> **Стан проєкту: ранній прототип.** Основний граф, мітки гаманців і баланси поки містять демонстраційні дані. Таблиця останніх транзакцій показує збережені спостереження доданих гаманців і буде порожньою, доки історію не синхронізують із налаштованим джерелом. Панель ризику завантажує сигнали аналітика для вибраної адреси й може врахувати точний збіг OFAC SDN після явної перевірки локального знімка; версія оцінки попередня й не є юридичним висновком або повною комплаєнс-перевіркою. У панелі гаманця доступна ручна синхронізація. Compose `sync-worker` періодично оновлює відстежувані Bitcoin і підтримувані EVM-адреси з цільовим інтервалом п’ять хвилин за достатньої потужності провайдера; це обмежене опитування історії, а не моніторинг у реальному часі чи всього mempool. Окремий граф зв’язків досліджує спрямовані шляхи до трьох переходів лише за збереженими EVM-подіями відправника й отримувача. Кожен перехід — окреме спостереження; шлях не доводить, що ті самі кошти пройшли весь маршрут. Контрагентів Bitcoin не виводимо. Підтримуються Ethereum, Base та Arbitrum One. Перевірка точної адреси за локально імпортованим знімком OFAC SDN доступна для Bitcoin та Ethereum. Не використовуйте демодані для операційних або комплаєнс-рішень.

## Про проєкт

Tracefold задуманий як OSINT-інструмент для розслідувань. Аналітик зможе почати з адреси, простежити перекази в підтримуваних мережах, зберегти підстави кожного зв’язку та перевірити сигнали ризику. Алгоритмічну оцінку не слід сприймати як доказ.

Прототип інтерфейсу містить демонстраційний оглядовий граф та окремий граф EVM-зв’язків зі збереженої історії, фільтри мереж, таблицю збережених спостережень і пояснювану версійну оцінку вибраного збереженого гаманця.

## Принципи

- Для кожної знахідки показувати мережу, адресу, посилання на транзакцію, джерело і час спостереження.
- Відокремлювати спостережувані транзакції від користувацьких міток і гіпотез аналітика.
- Показувати мережу як припущення, яке треба підтвердити: адресу формату EVM можна використовувати в Ethereum, Base, Arbitrum та інших сумісних мережах.
- Називати оцінку індексом ризикової експозиції, а не ймовірністю чи доказом порушення.
- Показувати повноту покриття й актуальність даних; не створювати враження, що відстежуються всі гаманці та мережі.

## Поточний стек

- **Frontend:** React, TypeScript, Vite та Tailwind CSS.
- **API:** локальний сервіс на Rust і Axum.
- **Постійні дані:** PostgreSQL; початкова міграція створює таблиці розслідувань, відстежуваних адрес і сигналів ризику.
- **Черга й координація:** Redis Streams для фонового worker-а; API також перевіряє доступність Redis у readiness endpoint.

API підтримує створення й перегляд розслідувань та відстежуваних адрес, ручну синхронізацію Bitcoin та вибраних EVM-мереж, сигнали ризику від аналітика й перевірку точної адреси за імпортованим знімком OFAC SDN. Таблиця останніх транзакцій показує збережені спостереження та їхнє джерело. Панель ризику завантажує сигнали вибраного гаманця й показує попередню оцінку версії моделі з внеском кожного сигналу; точний збіг OFAC додається як прямий санкційний доказ лише після явної перевірки, відсутність збігу не знижує бал. Compose worker оновлює відстежувані адреси тими самими обмеженими адаптерами провайдерів; див. [опис фонової синхронізації](docs/uk/continuous-sync.md). Граф зв’язків досліджує спрямовані EVM-шляхи до трьох переходів за збереженими подіями відправника й отримувача та позначає невідстежуваних контрагентів. Кожен перехід — окреме спостереження; шлях не доводить, що ті самі кошти пройшли весь маршрут. Входи й виходи Bitcoin не визначають контрагентів і не включені до графа. Основний граф і баланси використовують демодані. API не має автентифікації та призначений лише для локальної розробки. Знімок OFAC оновлюється вручну; комерційний сервіс перевірки не підключений.

- `GET` / `POST` `/api/v1/investigations`
- `GET` / `POST` `/api/v1/investigations/{investigation_id}/addresses`
- `POST` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/sync`
- `GET` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/transfers`
- `GET` / `POST` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals`
- `GET` / `PUT` / `DELETE` `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals/{signal_id}`
- `GET` `/api/v1/screening/address?network=ethereum&address=0x...`

Інструкція з імпорту знімка та покриття: [перевірка OFAC](docs/uk/ofac-screening.md).

## Синхронізація історії транзакцій

Ручна синхронізація історії доступна в інтерфейсі; Compose worker також періодично оновлює відстежувані адреси з цільовим інтервалом п’ять хвилин, якщо ресурсів провайдера й worker-а достатньо. Для Bitcoin використовується Blockstream Esplora. Для EVM — REST v2 Blockscout: Ethereum (chain ID 1), Base (8453) та Arbitrum One (42161); інші EVM-мережі не підтримуються. Налаштування: `BLOCKSCOUT_BASE_URL` (типове значення `https://api.blockscout.com`) та необов’язковий `BLOCKSCOUT_API_KEY` (передається як bearer-токен; доступ постачальника може вимагати ключ). Секрети в репозиторії не зберігаються. Див. [інструкцію з фонової синхронізації](docs/uk/continuous-sync.md).

Синхронізація Bitcoin зберігає попередню обмежену поведінку Esplora. Для EVM паралельно завантажуються звичайні нативні транзакції, успішні внутрішні перекази нативної валюти та події ERC-20. Зберігаються цілі початкові суми, адреса контракту й необов’язкова кількість decimals, індекс події, адреси сторін, блок, час і хост джерела. Кожен потік EVM обмежено 10 сторінками по 50 записів; `may_have_more_history` показує, що на межі ліміту у постачальника була наступна сторінка. Це обмежена історія, а не повний індекс: інші мережі, стандарти токенів і пропуски постачальника не охоплюються. Кілька подій однієї транзакції зберігаються окремо. Endpoint переказів повертає до 500 останніх записів. Worker опитує історію, але не відстежує кожен блок або mempool-подію.

## Запуск локального API

Потрібен Docker Compose.

```sh
docker compose --env-file .env.example up --build -d
```

Приклад конфігурації використовує облікові дані лише для локальної розробки. Compose публікує сервіси на loopback; не відкривайте цей API без автентифікації в мережу. Перевірити стан можна за адресами:

- `http://127.0.0.1:8080/health/live`
- `http://127.0.0.1:8080/health/ready` — перевіряє PostgreSQL і Redis.

Зупинити сервіси зі збереженням даних бази можна командою:

```sh
docker compose --env-file .env.example down
```

## Запуск прототипу інтерфейсу

Вимоги: Node.js 20.19+ або 22.12+ та npm.

```sh
npm ci
npm run dev
```

Vite виведе локальну адресу застосунку. Зараз він використовує вбудовані демонстраційні дані; ключ API не потрібен.

## Джерела даних і ліцензування

Синхронізація Bitcoin та вибраних EVM-мереж отримує історію через Blockstream Esplora й Blockscout вручну та через фоновий Compose worker. Ці дані описують транзакції, але не атрибутують осіб і не забезпечують повного аналізу ризику гаманців. Можна локально імпортувати офіційний знімок OFAC SDN і виконувати точну перевірку адрес Bitcoin та Ethereum; оновлення виконується вручну. API не використовує вебпошук OFAC для автоматичних запитів ([FAQ OFAC](https://ofac.treasury.gov/faqs/287)). Комерційні аналітичні сервіси потребують окремої ліцензії.
