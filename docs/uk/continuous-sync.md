# Фонова синхронізація історії гаманців

Додатковий сервіс `sync-worker` у Compose періодично оновлює історію кожної адреси під спостереженням через наявні адаптери Esplora та Blockscout. API працює і без worker-а; ручні endpoint-и синхронізації залишаються доступними.

```bash
docker compose up --build
```

Для запуску поза Compose потрібні ті самі `DATABASE_URL`, `REDIS_URL`, `BITCOIN_ESPLORA_URL` і змінні Blockscout:

```bash
cargo run --manifest-path apps/api/Cargo.toml --bin sync_worker
```

Планувальник сканує адреси пакетами за ключовим індексом до 1 000 записів кожні 30 секунд. Redis Streams зберігає не більше 10 000 очікуваних або активних задач. Адреси дедуплікуються; після ідемпотентного запису в PostgreSQL задача підтверджується. Задачі, що залишилися необробленими після збою worker-а, повторно забираються через 10 хвилин. Помилки провайдера й бази повторюються з експоненційною затримкою від 30 секунд до однієї години. Одна синхронізація обмежена вісьмома хвилинами. Після SIGINT або SIGTERM планування зупиняється, а поточна задача завершується перед виходом.

Цільовий інтервал для адреси — п’ять хвилин, якщо провайдер і worker встигають обробляти навантаження. За великої черги або обмежень провайдера фактичний інтервал збільшиться. Глибина історії обмежена адаптерами: Bitcoin — до 20 сторінок, кожен EVM-потік — до 10 сторінок. Worker не відстежує весь mempool, не атрибутує особи, не зберігає ключі та не підписує транзакції. Пауза окремої адреси поки відсутня: додавання адреси вмикає періодичне читання налаштованого публічного джерела.

Черга працює з доставкою «щонайменше один раз». Повторні задачі безпечні завдяки унікальним ключам і upsert-операціям у базі. У Compose для Redis увімкнене постійне зберігання; зберігайте том Redis під час перезапуску.
