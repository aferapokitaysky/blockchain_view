# API сигналів ризику

Ці endpoint-и зберігають введені аналітиком відомості для відстежуваної адреси. Вони не завантажують санкційні списки, не звертаються до комерційних сервісів перевірки та не обчислюють і не змінюють provisional-оцінку ризику в UI.

В API поки немає автентифікації; він призначений лише для локальної розробки. Не відкривайте його в недовірену мережу.

## Endpoint-и

Пара `{investigation_id}` і `{address_id}` має вказувати на адресу всередині цього розслідування.

| Метод | Шлях | Результат |
| --- | --- | --- |
| `GET` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals` | До 500 сигналів, спочатку найновіші. |
| `POST` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals` | Створити сигнал; відповідь `201 Created`. |
| `GET` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals/{signal_id}` | Отримати один сигнал. |
| `PUT` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals/{signal_id}` | Замінити всі поля, доступні для редагування; відповідь `200 OK`. |
| `DELETE` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals/{signal_id}` | Видалити сигнал; відповідь `204 No Content`. |

## Тіло запиту

Для `POST` і `PUT` потрібен JSON-об’єкт з усіма полями:

```json
{
  "signal_key": "manual_service_exposure",
  "category": "exposure",
  "severity": "medium",
  "source_name": "Analyst review",
  "source_reference": "case-42/evidence-2",
  "observed_at": "2026-11-15T10:00:00Z",
  "details": {
    "hops": 2,
    "note": "Analyst-entered observation"
  }
}
```

- `signal_key`: непорожній рядок до 120 символів.
- `category`: `sanctions`, `exposure`, `behavior` або `other`.
- `severity`: `critical`, `high`, `medium`, `low` або `informational`.
- `source_name`: обов’язковий непорожній рядок до 120 символів.
- `source_reference`: обов’язковий непорожній рядок до 512 символів. Це може бути URL або ідентифікатор запису джерела.
- `observed_at`: обов’язкова часова позначка RFC 3339. Значення більш ніж на п’ять хвилин у майбутньому відхиляється.
- `details`: обов’язковий непорожній JSON-об’єкт до 8 КіБ у серіалізованому вигляді.
- Розмір усього тіла запиту обмежений 16 КіБ. Невідомі поля відхиляються.

Пробіли на краях текстових полів прибираються перед збереженням. API зберігає вказані назву й посилання на джерело, але не перевіряє їхню достовірність, не завантажує згаданий запис і не заявляє про збіг із санкційним списком.

## Відповіді та помилки

Відповідь містить `id`, `tracked_address_id`, `signal_key`, `category`, `severity`, `source_name`, `source_reference`, `observed_at`, `details` і `created_at`. Ці поля походження дають змогу показати, хто або що надав сигнал і коли його помітили.

Помилки застосунку мають спільний формат `{ "error": { "code": "…", "message": "…" } }`:

- `400 invalid_json`: некоректний JSON або відсутній JSON Content-Type.
- `404 not_found`: адреса не належить розслідуванню або сигнал не прив’язаний одночасно до двох ID у шляху.
- `413 payload_too_large`: тіло запиту перевищує 16 КіБ.
- `422 invalid_request`: некоректне обов’язкове поле, enum, час або об’єкт `details`.
- `500 internal_error`: помилка сховища; внутрішні подробиці бази даних записуються лише в серверний лог.

## Межі доступу та використання даних

Кожне читання й зміна пов’язує сигнал із записом `tracked_addresses` одночасно за ID розслідування й адреси. Невідповідність повертає `404` і не розкриває, чи існує адреса або сигнал деінде. Для адреси повертається не більше 500 сигналів.

Сигнали зберігаються як відомості, введені аналітиком. API не об’єднує дублікати, не робить висновок щодо адреси, не звертається до зовнішніх сервісів і не змінює демонстраційний score frontend. Ліцензування джерел, строки зберігання, ідентифікація аналітика й автентифікація поки не реалізовані.
