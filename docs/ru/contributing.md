# Как внести вклад

Спасибо, что помогаете улучшать Tracefold. В изменениях важно отделять наблюдаемые факты блокчейна от предполагаемых связей и сигналов риска.

Другие языки: [English](../../CONTRIBUTING.md) · [Українська](../uk/contributing.md)

## Перед началом

- Проверьте существующие issues и код на предмет похожей функциональности.
- Для крупных изменений провайдера, схемы или скоринга сначала откройте issue и опишите источник данных и ожидаемое покрытие.
- Не добавляйте приватные ключи, seed-фразы, учетные данные провайдера, реальные пользовательские данные и неотредактированные логи в issues, тесты или фикстуры.

## Настройка разработки

Используйте Node.js 22, Rust stable, Docker Compose, PostgreSQL и Redis. Для локальной разработки скопируйте `.env.example` в `.env`; реальные ключи храните только в игнорируемом Git файле `.env`.

```sh
npm ci
docker compose up --build
```

Фронтенд запускается командой `npm run dev`. Compose поднимает API, PostgreSQL, Redis и sync worker. Перед изменениями потока данных или провайдеров изучите [архитектуру](architecture.md) и [синхронизацию истории](continuous-sync.md).

## Изменения и проверки

Держите pull request сфокусированным. Добавляйте миграции при изменении схемы и тесты для бизнес-правил, разбора ответов провайдера, курсоров и важных ошибок. Для каждого провайдера опишите источник, лицензию или условия использования, лимиты, пагинацию и известные пробелы покрытия.

Перед pull request запустите подходящие проверки:

```sh
npm run lint
npm run format:check
npm run test
npm run build
cargo fmt --manifest-path apps/api/Cargo.toml --all -- --check
cargo clippy --manifest-path apps/api/Cargo.toml --all-targets --all-features -- -D warnings
cargo test --manifest-path apps/api/Cargo.toml --all-features
```

Для полного набора Rust integration-тестов нужны PostgreSQL и Redis. GitHub Actions запускает frontend и Rust API проверки для каждого pull request.

## Чек-лист pull request

- Опишите поведение для пользователя и ограничения покрытия провайдера.
- Приложите ссылку на issue или объясните необходимость изменения.
- Добавьте тесты и обновите документацию EN/RU/UK, если изменились поведение, конфигурация, API или покрытие.
- Проверьте, что в Git не попали учетные данные, приватные ключи и персональные данные.
- Формулируйте комментарии и тексты интерфейса фактологично: риск-скор — это приоритет проверки, а не обвинение.
