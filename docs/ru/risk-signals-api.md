# API сигналов риска

Эти endpoint-ы сохраняют введённые аналитиком сведения для отслеживаемого адреса. Они не загружают санкционные списки, не обращаются к коммерческим сервисам проверки и не вычисляют и не меняют provisional-оценку риска в UI.

В API пока нет аутентификации; он предназначен только для локальной разработки. Не открывайте его в недоверенную сеть.

## Endpoint-ы

Пара `{investigation_id}` и `{address_id}` должна указывать на адрес внутри этого расследования.

| Метод | Путь | Результат |
| --- | --- | --- |
| `GET` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals` | До 500 сигналов, сначала самые новые. |
| `POST` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals` | Создать сигнал; ответ `201 Created`. |
| `GET` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals/{signal_id}` | Получить один сигнал. |
| `PUT` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals/{signal_id}` | Заменить все редактируемые поля; ответ `200 OK`. |
| `DELETE` | `/api/v1/investigations/{investigation_id}/addresses/{address_id}/risk-signals/{signal_id}` | Удалить сигнал; ответ `204 No Content`. |

## Тело запроса

Для `POST` и `PUT` требуется JSON-объект со всеми полями:

```json
{
  "signal_key": "manual_service_exposure",
  "category": "exposure",
  "severity": "medium",
  "source_name": "Analyst review",
  "source_reference": "case-42/evidence-2",
  "observed_at": "2026-11-15T10:00:00Z",
  "details": {
    "hops": 2,
    "note": "Analyst-entered observation"
  }
}
```

- `signal_key`: непустая строка до 120 символов.
- `category`: `sanctions`, `exposure`, `behavior` или `other`.
- `severity`: `critical`, `high`, `medium`, `low` или `informational`.
- `source_name`: обязательная непустая строка до 120 символов.
- `source_reference`: обязательная непустая строка до 512 символов. Это может быть URL или идентификатор записи источника.
- `observed_at`: обязательная временная метка RFC 3339. Значение более чем на пять минут в будущем отклоняется.
- `details`: обязательный непустой JSON-объект до 8 КиБ в сериализованном виде.
- Размер всего тела запроса ограничен 16 КиБ. Неизвестные поля отклоняются.

Пробелы по краям текстовых полей удаляются перед сохранением. API сохраняет указанные имя и ссылку на источник, но не проверяет их достоверность, не загружает упомянутую запись и не заявляет о совпадении с санкционным списком.

## Ответы и ошибки

Ответ содержит `id`, `tracked_address_id`, `signal_key`, `category`, `severity`, `source_name`, `source_reference`, `observed_at`, `details` и `created_at`. Эти поля происхождения позволяют показать, кто или что предоставило сигнал и когда он был замечен.

Ошибки приложения используют единый формат `{ "error": { "code": "…", "message": "…" } }`:

- `400 invalid_json`: некорректный JSON или отсутствует JSON Content-Type.
- `404 not_found`: адрес не принадлежит расследованию либо сигнал не относится одновременно к двум ID из пути.
- `413 payload_too_large`: тело запроса превышает 16 КиБ.
- `422 invalid_request`: неверно обязательное поле, enum, время или объект `details`.
- `500 internal_error`: ошибка хранилища; внутренние подробности базы записываются только в серверный лог.

## Область доступа и использование данных

Каждое чтение и изменение связывает сигнал с записью `tracked_addresses` одновременно по ID расследования и адресу. Несовпадение возвращает `404` и не раскрывает, существует ли адрес или сигнал где-то ещё. Для адреса возвращается не более 500 сигналов.

Сигналы хранятся как сведения, введённые аналитиком. API не объединяет дубликаты, не выносит вердикт об адресе, не обращается к внешним сервисам и не меняет демонстрационный score frontend. Лицензирование источников, сроки хранения, идентификация аналитика и аутентификация пока не реализованы.
