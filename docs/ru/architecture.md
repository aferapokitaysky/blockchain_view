# Архитектура

## Текущая реализация

В репозитории есть frontend на React, TypeScript, Vite и Tailwind и локальный API на Rust/Axum.

- Форма добавления кошелька распознаёт формат адреса Bitcoin, просит выбрать сеть для неоднозначного EVM-адреса и сохраняет расследования и адреса через локальный API.
- Граф, балансы, подписи узлов, основная таблица транзакций и панель риска пока используют статические демоданные. После синхронизации отдельное окно истории показывает сохранённые наблюдения Bitcoin и их источник.
- PostgreSQL — постоянное хранилище. Миграции создают `investigations`, `tracked_addresses`, `risk_signals` и `observed_transfers`.
- Redis подключён к проверке готовности API. Сейчас он не используется для кэша или фоновых задач.
- API без аутентификации и предназначен только для локальной разработки.

## Поток API и хранения данных

```text
Форма кошелька / локальный запрос API
                    |
               Rust + Axum
             /      |       \
     PostgreSQL    Redis   Настроенный Esplora endpoint
       записи      readiness  история Bitcoin по запросу
```

API создаёт расследования и отслеживаемые адреса и выводит их списки. Ручной запрос `POST` на синхронизацию получает историю Bitcoin-адреса у настроенного Esplora-совместимого сервиса, нормализует активность адреса и обновляет записи переводов в PostgreSQL. Отдельный `GET` возвращает до 500 последних сохранённых записей для адреса.

Для каждой транзакции сохраняются настроенный хост Esplora, время наблюдения, хеш транзакции, статус подтверждения, метаданные блока и суммы входов/выходов для отслеживаемого адреса. `spent_amount` — сумма входов, отнесённых к адресу; `received_amount` — сумма выходов на этот адрес. Суммы хранятся в целых сатоши и сериализуются строками, чтобы не терять точность. Это отдельные суммы входов и выходов, а не изменение баланса.

API сигналов риска сохраняет введённые аналитиком сведения в рамках расследования и отслеживаемого адреса. Каждый запрос проверяет оба ID пути относительно одной записи адреса. В сигнале остаются ключ, категория, серьёзность, имя и ссылка на источник, время наблюдения, структурированные детали и время создания. Размер тела запроса ограничен 16 КиБ, а `details` — 8 КиБ. Эти записи не загружаются и не проверяются автоматически и не меняют provisional-оценку frontend.

## Источник данных и ограничения

- История Bitcoin загружается только после вызова endpoint синхронизации. Планового опроса и постоянного мониторинга нет.
- Синхронизация запрашивает начальную страницу истории Esplora, где могут быть неподтверждённые mempool-транзакции, а затем проходит не более 20 страниц подтверждённой истории. Это до 500 подтверждённых транзакций плюс возможные mempool-записи из начального ответа.
- Endpoint переводов возвращает не более 500 последних записей. Если начальная страница содержит mempool-записи, синхронизация может загрузить больше 500 строк; endpoint чтения показывает ограниченный недавний список.
- Историю транзакций можно синхронизировать только для Bitcoin. Синхронизация EVM-истории не поддерживается. Данные Esplora — это наблюдения транзакций, а не атрибуция личности или полное покрытие адресов.
- API позволяет создавать, выводить списком и по ID, заменять и удалять сигналы, введённые аналитиком. Санкционный список и коммерческий сервис проверки не подключены; эти записи не меняют демо-оценку.

## Сеть и адреса

Строка адреса сама по себе не определяет сеть надёжно. Для каждого адреса и каждой транзакции нужно хранить идентификатор сети. Bitcoin-адрес проверяется по формату основной сети. EVM-адрес может быть валиден в нескольких сетях, поэтому интерфейс просит выбрать сеть; формат не отличает Ethereum от Base или Arbitrum. API нормализует EVM-адрес, но не определяет сеть автоматически.

## Надёжность и безопасность

- Проверяйте входные данные и сохраняйте связь адреса с расследованием в каждом запросе.
- Ограничивайте время запросов поставщика и используйте идемпотентную запись по адресу и хешу транзакции.
- Сохраняйте источник и время наблюдения, чтобы аналитик мог проверить происхождение и актуальность данных.
- Для локального использования API привязан к loopback. У него нет аутентификации; не открывайте его в недоверенную сеть.
- Явно отделяйте демоданные интерфейса от данных поставщика, пока граф не подключён к endpoint-у синхронизации.
